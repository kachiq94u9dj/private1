# Instagram 友達ダッシュボード 要件定義

## 目的

Instagram アカウント（1つ）の友達（フォロワー・フォロー中）を一覧・整理し、
イベントごとに「誰を招待するか・誰が参加するか」を管理できるようにする。

## 決定事項（ヒアリング結果）

| 項目 | 決定内容 |
|---|---|
| 入力データ | Instagram 公式「情報をダウンロード」の **HTML 形式** ZIP |
| 保存先 | 既存 Supabase プロジェクト `claude-usage-tracker` に新テーブルを追加 |
| 利用者 | 自分ひとりのみ（ログイン必須。RLS で本人の行しか読めない） |
| 対象アカウント数 | 1つ |
| 取り込み範囲 | フォロワー / フォロー中（フォローした日時）＋ 1対1 DM の **件数と最終日時のみ** |
| 見込み客の管理方法 | イベントを登録し、友達ごとに参加ステータスを記録 |
| 出力 | @ユーザー名の一括コピー、プロフィールへのリンク一覧 |
| 置き場所 | 既存 Next.js アプリに `/instagram` ページとして追加 |

## 機能要件

### F1. ログイン
- メールアドレス宛のマジックリンクでログインする。
- 未ログイン時はデータを一切表示しない。

### F2. データ取り込み
- ブラウザで ZIP を選択すると、**ブラウザ内で** HTML を解析する。
- 解析対象:
  - `followers_*.html`（フォロワー、フォローされた日時）
  - `following.html`（フォロー中、フォローした日時）
  - `messages/inbox/*/message_*.html`（1対1 DM の件数・最終日時）
- **DM の本文・写真などは Supabase に送らない。** 送るのはユーザー名・日時・件数だけ。
- 再取り込み時は既存のメモやイベント情報を残したまま、フォロー状態と DM 件数を更新する。
  今回のデータに出てこない人は「フォロワー/フォロー中ではない」に更新する（削除はしない）。
- グループ DM は対象外。DM のスレッドとユーザー名の対応が取れなかったものは件数を表示する。

### F3. 友達ダッシュボード
- 集計: 友達総数、フォロワー数、フォロー中数、相互フォロー数、DM したことがある人数。
- 一覧: ユーザー名（プロフィールへのリンク）、関係（相互 / フォロワーのみ / フォロー中のみ）、
  フォローされた日、DM 件数、最終 DM 日、メモ。
- 検索（ユーザー名・メモ）、関係での絞り込み、並び替え（ユーザー名 / DM 件数 / 最終 DM / フォロー日）。
- メモの編集。

### F4. イベント管理
- イベントの作成・編集・削除（名前、日付、場所、メモ）。
- 友達一覧から選んでイベントに追加する。
- 参加ステータス: `候補` → `招待済み` → `返事あり` → `参加` / `不参加`、イベント後に `来場`。
- ステータスごとの人数を表示し、ステータスで絞り込める。

### F5. 出力
- 絞り込んだ人の `@ユーザー名` を改行区切りで一括コピー。
- 絞り込んだ人のプロフィールへのリンク一覧（クリックで Instagram が開く）。
- DM の自動送信は Instagram の規約違反になるため作らない。

## 非機能要件
- 個人情報保護: RLS で `owner_id = auth.uid()` の行のみ読み書き可能。匿名キーでは何も読めない。
- 既存の Claude 利用量ダッシュボード（`/`）には影響を与えない。

## 対象外（今回は作らない）
- DM 本文の保存・キーワード検索、自動スコアリング、タグ付け、CSV 書き出し、複数アカウント、スタッフ共有。
